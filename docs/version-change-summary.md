# 软著材料生成工具修改说明

生成日期：2026-07-23

## 说明

当前客户安装包和应用版本为 `0.1.9`。以下按照近期交付过程中的“阶段版本”整理，用于说明各轮更新解决的问题和新增能力，便于客户验收、内部交接和后续发版记录。

## V0.1.9 请求地址、零令牌与正式 React 交付版

主要更新：

- 高级设置支持填写并替换 GPT 请求地址；保存后请求地址和 API Key 均不回显，只显示隐藏配置状态。
- 恢复 `Default Template` 模式，明确标注“不消耗 token”，并在 Electron 子进程中清空文本/图片模型地址和密钥。
- 正式 GPT 流程接入结构化操作契约、35 页 React 后台样本、24 张互补操作页、统一 `SharedConfirmDialog`、DOM 图文语义门禁和截图检查点 v13；35/24 是当前 8 模块后台样本结构，不是固定页数。
- 打包环境优先使用 Electron-as-Node 从 `app.asar` 运行 Vite，避免系统 Node 无法解析 asar 导致 55% 构建失败；缓存 React CSS 会清理残缺尾规则，避免页面样式污染公共主题。
- 扩展统计图日期/时间范围与业务图例识别，并允许手册使用结构化 DOM 摘要中的字段标签，不要求逐字复述整段帮助文案。
- 修复 Default Template 随机选错行业、App 被自动“工作台”措辞误判为后台、68 分蓝图和空结构化操作仍被放行的问题；名称/原始业务补充与蓝图行业不一致时停止交付。
- 修复操作弹窗标题重复换行、空白或状态徽标按钮裁图、同类操作页只改标题仍被相似度门禁豁免，以及 `business_operator` 和交通硬编码样例泄漏到非交通材料的问题。
- 共享应用外壳改为读取软件视觉身份，在 `side_menu / top_tabs / rail` 三种导航中按项目选择，并直接使用真实模块名和项目配色，避免多个软件重复出现同一套通用顶部导航。
- 确认页按钮裁图严格限定在 `SharedConfirmDialog` 内，排除遮罩后的背景按钮；按钮图片统一高度和 Word 插入尺寸，查询、导出、查看、保存、确认、取消等操作在手册中分别解释具体用途和状态影响。
- 新增 `vr_spatial_modeling` 行业子型，测绘、GIS、点云、倾斜摄影、坐标配准和模型分块项目不再回退到 VR 安全培训身份；通用 VR 体验描述改为中性的场景、模型、空间作业和质量分析语义。
- 客户安装器内置 Python、LibreOffice、Chromium、Chromium Headless Shell、ffmpeg 和 winldd；本轮最终安装器大小 `604,475,519` 字节，SHA-256 为 `F5D755E247F2BE3269EDEF3627D36AE217639E02BEA3A3C373DE714D192F888C`。
- 修复手册 FAQ 孤页：常见问题处理整节从新页开始，避免最后一页只有少量散落文字；新增分页回归，保持正文密度硬门禁有效。
- 修复 image2 临时失败提示误导：重试保持 `1280x720` 支持尺寸，只压缩提示词；错误报告保留完整 HTTP 状态序列，并优先提示 429、5xx 和超时类上游故障。
- 修复深色高密度参考图误判、Windows 截图当前页偶发 `Errno 22`、轨道施工质量系统误套客运线路拓扑门禁，以及输入框 placeholder 未被手册语义校验识别的问题。
- 本地模板蓝图改为按真实领域生成不同业务对象、字段、动作、结果证据和跨模块协同链路，并新增跨模块同质化门禁；Default Template 仍不调用文本或图片模型。

## V0.1.0 基础材料生成版

本版本完成软著材料生成工具的基础闭环。

主要更新：

- 新增 Electron 桌面端，可在本地填写软件名称、版本、源码语言、软件类型和业务补充后生成材料。
- 新增后端材料生成流程，可生成说明书、源码鉴别材料、申请信息表和材料包。
- 支持 Word、PDF 和 ZIP 输出。
- 支持从生成的源码工程中提取源码鉴别材料，而不是直接拼接代码文本。
- 支持 Java、JavaScript、Python、PHP、C#、C++、HTML 等源码语言入口。
- 最终客户 ZIP 收敛为 5 个交付文件：说明书 Word、说明书 PDF、申请信息表 TXT、源码材料 Word、源码材料 PDF。

解决的问题：

- 打通从输入软件信息到生成软著申请材料包的完整流程。
- 初步满足软著材料的文件结构、页数和交付格式要求。

## V0.1.1 安装包与本地运行时版

本版本重点解决客户机器上“不装开发环境也能运行”的问题。

主要更新：

- 接入 `electron-builder`，支持生成 Windows NSIS 安装器。
- 新增客户版打包脚本 `npm run pack:win:customer`。
- 内置 Python runtime，安装后优先使用安装目录内的 Python 执行后端生成任务。
- 内置 Playwright Chromium Headless Shell，用于稳定生成界面截图。
- 内置 LibreOffice runtime，用于将 Word 转换为正式 PDF。
- 支持普通安装包和客户预置安装包两种打包方式。
- 客户预置安装包可内置 GPT 网关配置和 API Key。

解决的问题：

- 避免客户电脑缺少 Python、浏览器或 LibreOffice 导致生成失败。
- 避免客户手工配置复杂运行环境。
- 提升 PDF 输出质量，减少简版 PDF 兜底。

## V0.1.2 GPT-only 真实项目生成版

本版本将正式生成路径从模板化生成升级为 GPT 驱动生成。

主要更新：

- 正式生成收敛为 GPT-only：名称理解、产品蓝图、技术架构、说明书正文和界面蓝图均由 GPT 生成。
- 蓝图和正式内容统一使用 `gpt-5.5`，不再自动降级到低配模型。
- 新增软件名称理解，根据软件名称自动推断业务领域、目标用户、关键词和避免方向。
- 新增 GPT 产品方案生成，先生成业务对象、流程、指标、规则和模块明细，再驱动后续材料。
- 新增 GPT 自动选择技术架构，根据软件类型自动选择 Spring Boot、ASP.NET Core、FastAPI、移动端前后端分离、网关服务、边缘服务等架构方向。
- 说明书、源码、截图和信息表共享同一份产品方案，减少材料之间不一致。

解决的问题：

- 避免所有项目像同一套模板。
- 避免让客户手工选择源码架构和技术特点。
- 提升材料的业务真实性和项目差异化。

本版本重点提升说明书配图质量，让截图更像正式软件。

- 新增多种后台布局变体：风控控制台、地图态势、链路流程、工单流程等。
- 截图增加正式业务系统细节，包括应用外框、顶部用户区、工作区标签、业务编号、表格复选框、分页、行内操作、选中记录详情、处理轨迹、附件和导出状态。

解决的问题：

- 修复配图看起来假、重复界面多、标题字号不统一的问题。
- 提升不同类型软件截图的差异化。
- 让说明书截图更接近人工编写软著材料的质量。

## V0.1.4 源码质量与真实性校验版

本版本重点提升源码材料质量和交付前自检能力。

主要更新：

- C# 源码生成扩展为 ASP.NET Core 风格工程，包含 Controller、Service、Repository、Model、Query、统计、审计、导出和操作追踪等文件。
- Java 源码材料先保证 3000 行有效源码，再按 50 行一页对齐。
- 源码鉴别材料过滤低信息行，减少单独括号、空结构和无意义样板代码进入 Word。
- 新增源码材料质量指标，包括低信息行比例、访问器样板比例、业务逻辑行比例等。
- 新增 `validation_report.json`，记录源码文件清单、SHA-256、产品蓝图 hash、交付文件 hash、ZIP 条目、占位符/乱码扫描和业务命中情况。
- 新增 `materials_manifest.json` 内部证据链清单，记录源码页码与真实文件行号范围、说明书引用映射和 PDF 转换信息。
- 桌面端结果区新增真实性评分、规范性评分和交付建议。

解决的问题：

- 修复源码中“一个括号占一行”等低质量展示问题。
- 提升源码鉴别材料的可读性和真实项目感。
- 交付前可以判断材料是否建议交付，而不是只看 ZIP 是否生成。

## V0.1.5 长流程稳定性、失败恢复与加速版

本版本重点解决 GPT 生成耗时长、失败后要重来的问题。

主要更新：

- 蓝图生成升级为两段式 GPT 请求：先做名称理解，再生成 8-10 个可编辑模块草案。
- 修复“生成蓝图”长时间卡住的问题，增加启动、超时、失败、成功等进度事件。
- 正式生成复用用户确认后的蓝图，避免确认后再次重复做名称理解。
- 新增失败恢复入口：生成失败后可选择“保留蓝图重试”“继续修改蓝图”“新建任务”。
- 新增阶段缓存能力，产品蓝图、技术架构、说明书正文、UI 蓝图成功后会写入本地缓存。
- 失败后重试可复用同一蓝图、模型和生成策略下的成功阶段，跳过已完成的 GPT 请求。
- 说明书公共章节或模块批次失败时，会自动拆分为单章节/单模块继续补齐。
- 默认生成策略切换为平衡加速，产品蓝图、说明书正文和 UI 蓝图默认启用 2 路小批次并发。
- 新增 `llm_trace.jsonl` 诊断日志，记录请求阶段、耗时、状态码和错误摘要，不记录 API Key 或 Base URL。

解决的问题：

- 修复客户侧“生成说明书模块章节 4/4”遇到 504 后直接失败的问题。
- 减少 GPT 网关波动导致的整包失败。
- 失败重试时可从最近成功阶段继续，降低时间和 token 浪费。
- 让长流程更可视化、更可诊断。

## 总体变化汇总

相比最初版本，当前版本的核心变化可以概括为：

- 从“模板材料生成”升级为“GPT 生成真实项目材料”。
- 从“人工选择架构和软件类型”升级为“根据软件名称自动判断类型、自动选择技术架构”。
- 从“只生成材料文件”升级为“生成、截图、PDF、ZIP、校验、证据链一体化”。
- 从“失败后整包重跑”升级为“保留蓝图、阶段缓存、失败重试、错误脱敏”。
- 从“截图像模板后台”升级为“按行业和软件类型生成差异化正式软件截图”。
- 从“开发机可运行”升级为“客户安装包内置 Python、Playwright 和 LibreOffice，可直接安装使用”。

## 当前仍需后续优化

- 安装包仍显示 `0.1.0`，后续正式对外发版建议同步调整语义化版本号。
- 应补充正式应用图标、`description` 和 `author`，减少默认 Electron 痕迹。
- 建议增加代码签名证书，降低 Windows 安全提示。
- Java、JavaScript、Python 的真实服务截图模式还可继续补齐，目前 C# 已支持启动生成项目后截图。
- GPT 网关仍可能偶发 503、504 或读超时，后续可继续增强模型健康检查和更清晰的重试提示。
