- 使用客户最近保存的安装版配置，文本主模型 gpt-6-sol、图片模型 gpt-image-2；没有更换网关、密钥或改为本地模板。

- 对可恢复的生成失败最多额外续跑一次，复用已有缓存。续跑成功不回填首次成功数。名称理解失败的样本仍计入整单分母。
- 沿用桌面默认文本超时与重试设置；脚本为草案阶段设 150 秒外层上限，正式生成和续跑分别设 1800 秒上限；触发上限会明确记为测试中止。
- 未修改业务源码、质量阈值或客户 API 配置；没有把部分页面、HTTP 200 或草案成功算作完整交付。

- 请求数量包含内置重试、页面修复及一次续跑；被取消的请求不能据此断言供应商未计费。
- 当前 provider 日志未保留供应商完整 usage、finish_reason 或账户计费凭据，因此本次不编造 Token 数和人民币费用；API 成本需另对照供应商账单。

## 已确认的问题与结论边界

- 剪辑样本两次均在 timeline_editing 页面 JSON 解析失败；教育样本两次均在 class_course 页面 JSON 解析失败。前两单首次材料生成分别运行约 9.4 和 8.7 分钟后停止。
- 教育样本首次 dashboard 和 class_course 输出分别为 6326、7246 字符，超过当前 6000 字符上限；压缩修复后 class_course 返回 2262 字符，仍无法解析 JSON。续跑再次出现超长和修复后解析失败。
- 医疗样本首次和续跑均在产品身份蓝图阶段失败，各自内部两次 JSON 格式尝试均未成功，因此没有进入说明书、图片和页面生成。
- 本轮未观察到 API 超时、鉴权失败、限流或服务端错误；4 个请求错误事件均为程序在页面失败后主动取消相邻请求。不能仅靠增加超时解决本次已观察到的问题。
- JSON 格式无效已被确认，具体由模型输出、网关处理或输出预算截断中的哪一项导致，现有日志不足以判断；不将待验证假设当作根因。
- 本轮均未产出通过门禁的最终材料包；完整截图、DOCX/PDF 排版与 ZIP 内容验收仍待生成链路修复后验证。建议先解决结构化输出故障，再安排最终版验收。

## 优先优化建议

1. 先处理蓝图与 PageSpec 等全链路结构化输出可靠性：记录 finish_reason、usage、解析错误位置和脱敏响应片段；区分 JSON 被长度限制截断、语法错误、空内容和业务校验失败。当前正常页面输出预算 1600、格式修复预算 1200，修复预算更小是否导致截断属于待验证假设，不能仅凭解析错误定论。
2. 对复杂页面按结构拆分，明确每个区域的数据量和必需字段；使用供应商支持的严格 JSON Schema，并根据真实输出量设预算。只对失败页面做有限格式修复，保留质量门禁和已有页面缓存，避免整单从头重跑。
3. 修复后先用本轮失败样本做相同配置对照，再开展至少 20 个多类型完整材料包验收。首次成功率与续跑成功率分开统计；只有真实通过 DOCX/PDF/截图/ZIP 和质量门禁，才能作为最终版交付依据。
