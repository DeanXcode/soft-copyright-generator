# 生成成功率与速度优化记录

日期：2026-11-13。当前阶段优先减少失败、重复调用和等待，暂缓内容质量专项；原有 API 明文测试配置未修改。本次修改已进入源码，未制作新客户安装器。

## 已实现

1. **精简逐页上下文**：当前模块仍保留完整要求，其他模块仅传 key/title，原始功能描述最多保留 1200 字符，JSON 去除排版缩进。已确认的蓝图、当前页面和当前模块继续作为请求依据，不修改输入对象。
2. **减少已知字段的重复生成**：对无操作动作的页面，或 trigger/post_state/result_evidence 已齐全的操作页面，由本地注入已确认的交互契约，允许模型省略重复契约；缺少主操作时沿用现有规范化逻辑补齐。部分契约不完整时仍要求模型输出，不跳过页面结构及可渲染性检查。
3. **并发遇错后自动恢复**：自动并发模式遇限流、网关、连接错误或超时降至 1；连续 4 次无重试成功后恢复本任务配置的并发数，通常为 2。恢复后再次遇错仍可降级，避免一次瞬时故障使后续几十页永久串行。固定并发模式保持原行为。
4. **说明书统一有界队列**：公共章节和模块正文共用一个线程池，公共章节中的慢请求不会阻塞全部模块任务；并发上限保持默认 2。由协调线程合并结果及保存断点，鉴权/配置等致命错误阻止继续提交；同一批已完成的成功结果在抛出致命错误前先保存，供下次续跑。
5. **补齐观测数据**：逐次记录请求字符数、精简前后的载荷字符数；生成报告记录最终并发上限及并发恢复次数。日志不新增密钥、请求地址或提示词正文。

## 真实 API 对照

使用当前已安装客户端的 gpt-6-sol 配置，复用剪辑、教育、医疗三个旧样本的上游业务输入。对全部 97 个页面在本地构造请求并比较字符数，选每类一个操作页做前后各一次真实请求；不启用网络重试或格式修复轮，返回结果经过本地 PageSpec 解析、规范化及 JSX/CSS 生成。

“优化前”函数由当前实现临时还原完整上下文、缩进 JSON 和模型回传交互契约要求，其他前阶段修复保持一致。前后调用交替排序，但没有控制网关缓存、排队或模型随机性，不属于严格延迟基准。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 97 页请求输入总字符数 | 3,103,057 | 922,681 |
| 本轮操作页一次通过数 | 3/3 | 3/3 |
| 剪辑页面耗时 | 22.582 秒 | 36.287 秒 |
| 教育页面耗时 | 5.678 秒 | 21.821 秒 |
| 医疗页面耗时 | 26.083 秒 | 25.110 秒 |
| 三页平均耗时 | 18.114 秒 | 27.739 秒 |

**已证实请求字符量减少 70.27%；本轮优化后平均延迟更高，没有证实真实 API 提速或成功率提升。** 字符数减少不能直接换算为 Token、账单或整单提速比例。网关报告的 usage 原样保存在脱敏数据中，未据此估算费用。

上述是 6 次页面请求，不含新蓝图、说明书、图片、浏览器截图和完整材料包，不能称为 6 单整单成功。历史正式整单首次成绩仍为 2/3（66.7%）；教育缓存续跑成功不回填首次成绩。

## 下一阶段建议

1. 在新输出目录完成至少三类整单真实生成，统计首次完整成功率、阶段耗时、重试次数及最终 ZIP；失败后的续跑另列，确认调度改动是否实际缩短整单时间。
2. 若网关单次请求仍是耗时主因，再用相同输入比较候选模型或线路的延迟和错误率，按测量结果调整并发；暂不凭本轮小样本继续提高默认并发或缩短超时。
3. 实测达标后制作候选安装器并验证客户安装、首次启动和失败续跑。内容质量专项按当前优先级后移。
