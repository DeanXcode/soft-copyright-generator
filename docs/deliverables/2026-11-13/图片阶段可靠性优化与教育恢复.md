日期：2026-11-13

## 范围与统计口径

本阶段按“成功率和速度优先”处理图片接口长时间失败及续跑时的重复请求。保持原有客户端 API 明文配置、密钥、渠道与模型设置，使用安装包内嵌 Python，从原教育失败现场的独立副本续跑。没有手工修改生成内容，没有制作新安装器。

上一轮三单首次完整成功仍为 **1/3（33.3%）**。本阶段教育恢复是续跑结果，不回填为首次成功，不与从头生成耗时直接比较。

## 原因证据

- 教育任务原先四次图片调用均返回 HTTP 524，单次耗时约 126 秒，图片请求及退避合计约 514.56 秒。该次失败发生在风格参考图阶段，尚未进入逐页生成。
- 同次任务风格提示词文本生成耗时 68.43 秒，提示词已经落盘；旧续跑逻辑仍会重新生成这份提示词。
- 本阶段只读诊断：携带原配置密钥的模型列表请求返回 200，目标图片模型可见；不带密钥的对照返回 401。列表结果只证明该接口的鉴权和列表权限，不能单凭它证明图片推理可用。
- 随后真实图片生成以原配置首请求成功，耗时 **44.735 秒**，保存 1280×720 图片，962,795 字节。说明原密钥本次可以完成图片生成。不能据此确定之前上游超时的内部原因，或保证渠道持续可用。

## 已实现优化

1. **连续慢故障保护**：默认两次连续、单次至少 60 秒的可重试网络故障后停止重复等待，保留失败节点供续跑；快速临时错误仍按原配置有限重试。图片内容校验失败不误归为慢网络故障。相关阈值为内部环境配置，不要求新手客户手动设置。
2. **不截断正常慢生成**：连接超时最长 15 秒，图片读取仍保留原配置 220 秒。该策略不是整个生成流程的硬耗时上限；默认慢故障限制也可能减少第三、第四次请求恢复的机会，可由内部配置调整。
3. **失败后复用提示词**：同一视觉缓存标识、参考页面及尺寸匹配，且提示词有效时复用已保存结果；损坏、短文本、非法关键词类型、乱码及身份不匹配均拒绝复用。仍用当前任务上下文重新组装最终图片请求文本。
4. **请求与诊断修复**：根路径误返回 HTML 时，回退标准接口不再消耗网络重试预算；及时关闭响应与会话，记录实际重试、累计耗时及停止原因。

用虚拟时钟复现四次各 126 秒的持续 524，新策略两次后停止，合计 253.5 秒；原四次策略为 514.5 秒。这是确定故障下的模拟等待缩短，**不是本次真实成功提速数据**。本次真实图片首请求成功，未触发慢故障保护。
