# 响应完整性优化与真实 API 回归

日期：2026-11-12。状态：响应完整性修复及三单正式回归已结束，首次完整材料成功 **2/3（66.7%）**；教育样本在最后的统计页截图门禁失败。当前修改为工作区源码，尚未制作新安装包，尚不能宣布最终交付达标。

## 本阶段解决的问题

此前三个样本的首次完整生成和一次续跑均为 0/3。当前客户端文本密钥已验证有效，但接口返回 HTTP 200、finish_reason=stop 和 [DONE] 仍可能给出无效 JSON。旧代码以首个左花括号到最后一个右花括号截取正文，外层结束符缺失时可能截到内部对象结尾，导致误导性的错误定位。独立的 PageSpec 长度限制也曾阻塞生成。

1. **统一解析入口。** 产品蓝图、技术架构、界面蓝图、说明书、功能推断、前端组件和 PageSpec 共用完整对象解析器，不再截取内部花括号。保留原始 JSON 错误行列。
2. **有限且可追溯的语法修复。** 仅当内部数组/对象和字符串均闭合、只剩根对象未闭合、末尾完整值为数组/对象时，允许去除末尾多余逗号并补一个根结束符。每次记录修复事件。不补业务字段、不闭合截断字符串或内部容器，解析后继续执行原业务校验。
3. **检查响应结束证据。** 请求日志增加 finish_reason、服务商报告的 usage、流结束标记和损坏事件数；支持多行 SSE 及省略事件空行的兼容网关。没有结束证据或事件损坏按网络类错误处理；length/content_filter 等异常结束进入既有有限格式修复。鉴权错误保持立即失败。
4. **控制 PageSpec 长度。** 正常及唯一修复轮输出预算均为 2400 Token，提示紧凑 JSON、目标 4500 字符、硬上限 6000。先检查原始响应不超过 24000 字符，再在规范化前对全部紧凑 JSON 执行 6000 字符限制；仅去排版空白，不通过丢未知字段规避上限。交互契约及结果证据继续保留。

API 明文测试配置未修改，未覆盖项目旧配置。Default Template 零 Token 行为、默认 Headless Shell 截图及原交付门禁均保留。没有将模板成功冒充真实 API 成功。

### 教育样本的首次失败诊断（修复前）

原始错误为 `statistics 页面存在文字溢出、越界或重叠：div.chart-grid-lines: 4`。使用原生成项目及项目现有 Playwright Headless Shell 做本地复现，没有新的付费 API 请求、没有修改生成材料或源码：

- 同样检测到 `kind=occlusion`，既有自动修复后仍存在；页面为 PageSpec，原有逻辑有意跳过旧页面的缩字、裁剪及隐藏装饰块修复，不宜用这些措施直接掩盖问题。
- 可见的第三张指标卡超出指标区块，被后续图表覆盖；图表内容高度仅约 50 像素，柱形显示空间不足。需要修正区块尺寸、内容高度和滚动布局，而非把教育任务记为成功。
- 页面规格中的指标是 90.0%、90.0%、75.0%，运行时 `updateCards` 却按接口记录数量覆盖指标值，抽查页面显示为 4。`updatePageSpecRegions` 同时将图表标签换成通用记录名，存在业务语义丢失。
- 当前渲染器未正确承接该规格中的多点 `series.points` 和自定义表格字段，分别落入 66／72／78 的默认图表值及“统计报表1”等通用表格值。柱高另依固定样式取值，与实际数值未绑定。即使排版门禁通过，也需要按字段和数据契约核验这些内容，避免“数据存在但展示失真”。

本地证据：`tmp/education-layout-review/evidence.json`、`tmp/education-layout-review/statistics-before.png`、`tmp/education-layout-review/statistics-after-existing-repair.png`。该复现用于定位，不作为新的整单成功样本。
